# AutoBuy-MofidBroker

ربات خرید خودکار برای کارگزاری مفید (پلتفرم EasyTrader)، بازنویسی‌شده با **Playwright**.
وارد می‌شود، **سفارش را خودش آماده می‌کند** (نماد، قیمت، تعداد)، منتظر ساعت دقیق بورس
می‌ماند و سپس دکمه خرید را تا تأیید شدن تکرار می‌کند.

راهنمای انگلیسی: [README.md](README.md)

---

## ویژگی‌ها

- **آماده‌سازی کاملاً خودکار** — رفتن به نماد، باز کردن برگه خرید، پر کردن قیمت و تعداد؛ دیگر خبری از `Press ENTER` دستی نیست
- **حالت‌های قیمت** — `ceiling` (سقف قیمت، پیش‌فرض)، `reference` (قیمت پایانی) یا `fixed` (قیمت ثابت)
- **بازخوانی ایمنی** — نماد برگه بررسی می‌شود و تعداد/قیمت بعد از پر شدن دوباره خوانده می‌شوند؛ در صورت مغایرت ربات خرید نمی‌کند
- **تایمینگ دقیق** — منتظر ساعت سرور بورس (نه ساعت سیستم)
- **پشتیبانی چند نمونه** — اجرای هم‌زمان چند نماد با پروفایل‌های جداگانه کروم
- **تأیید سفارش** — بعد از خرید موفق، لیست سفارش‌ها بررسی می‌شود
- **یافتن قوی دکمه خرید** — سلکتور اصلی `data-cy` به همراه چند fallback و کلیک با تلاش مجدد
- **تشخیص پیام بورس** — خواندن toast و اسکن DOM برای پیام فارسی/انگلیسی؛ کلمات خطا **قبل** از کلمات موفقیت بررسی می‌شوند
- **حالت دستی** — سوییچ `--manual` همان رفتار قبلی (آماده‌سازی توسط خودتان) را برمی‌گرداند
- **پیکربندی محیطی** — اعتبار و تنظیمات از `.env` یا متغیرهای محیطی
- **بستن منظم** — Ctrl+C مرورگر را کامل می‌بندد
- **بدون ChromeDriver** — Playwright با کروم نصب‌شده کار می‌کند؛ دیگر نیازی به هم‌نسخه کردن درایور نیست

## نصب

```bash
pip install -r requirements.txt
```

Playwright از **گوگل کروم نصب‌شده** استفاده می‌کند (`channel="chrome"`)، پس دانلود مرورگر لازم نیست.
اگر کروم نصب نیست:

```bash
playwright install chromium
```
و در `driver.py` مقدار `channel="chrome"` را به `channel="chromium"` تغییر دهید.

فایل `.env` را از قالب بسازید:

```bash
copy .env.example .env
# فایل .env را ویرایش و اعتبار را وارد کنید
```

| `API_ORDER_WINDOW_GRACE` | `8` | بازار ۸:۴۵ تا ۱۲:۳۵ و ثبت سفارش ۸:۴۵ تا ۱۲:۳۰؛ اگر باز شدن بیشتر از این فاصله باشد هشدار می‌دهد |
| `TOKEN_CACHE` | `true` | استفاده مجدد از توکن اجرای قبل و رد کردن لاگین (ADR-005) |

## استفاده

### نمونه تکی (آماده‌سازی خودکار)

```bash
python main.py --time 08:44:58 --symbol فولاد
```

`--symbol` روی `SYMBOL` اولویت دارد؛ ساعت هدف به‌صورت پیش‌فرض از `DEFAULT_BUY_TIME` خوانده می‌شود.

### بدون تأیید سفارش

```bash
python main.py --time 09:00:00 --no-verify
```

### حالت دستی (رفتار قدیمی)

```bash
python main.py --manual
```

ربات لاگین می‌کند و سپس متوقف می‌شود تا شما خودتان برگه خرید را پر کنید.

### چند نمونه هم‌زمان (هر ترمینال یک نماد)

ترمینال ۱:
```bash
INSTANCE_ID=folad CHROME_USER_DATA_DIR=C:\chrome-folad SYMBOL=فولاد QUANTITY=10 python main.py
```

ترمینال ۲:
```bash
INSTANCE_ID=kalan CHROME_USER_DATA_DIR=C:\chrome-kalan SYMBOL=کالن QUANTITY=5 python main.py
```

هر نمونه پروفایل کروم جدا دارد (بدون تداخل کوکی/لاگین) و لاگ‌ها با شناسه نمونه مشخص می‌شوند.

## جریان کاری

۱. **احراز هویت** — اگر توکن ذخیره‌شده هنوز معتبر باشد بدون لاگین وارد می‌شود، وگرنه لاگین خودکار با Playwright
۲. **آماده‌سازی** — خودکار: در حالت API جستجوی نماد و سقف قیمت با HTTP، وگرنه جستجوی نماد → انتخاب نتیجه دقیق → برگه خرید → تعداد → قیمت بر اساس `PRICE_MODE` → بازخوانی و بررسی
۳. **انتظار ساعت** — تا رسیدن ساعت بورس به زمان هدف
۴. **خرید خودکار** — تا ۲۵ کلیک با فاصله ۱۰۰ میلی‌ثانیه تا تأیید بورس
۵. **تأیید** — بررسی لیست سفارش‌ها

اگر در هنگام آماده‌سازی زمان هدف گذشته باشد، ربات **بدون خرید** خارج می‌شود.

## عیب‌یابی

| مشکل | راه‌حل |
|------|-------|
| «لاگین ناموفق» | اعتبار در `.env` را چک کنید |
| «نماد/تعداد تنظیم نشده» | `SYMBOL` و `QUANTITY` (> ۰) را تنظیم کنید یا از `--manual` استفاده کنید |
| «Order ticket opened for X, expected Y» | انتخاب نماد دو بار اشتباه شد؛ املای نماد را چک کنید — ربات به‌جای معامله نماد اشتباه متوقف می‌شود |
| «Layout overlay still active» | یک مودال/پنل صفحه را قفل کرده؛ دوباره اجرا کنید (ربات Escape و کلیک روی backdrop را خودش امتحان می‌کند) |
| «ساعت بورس پیدا نشد» | صبر کنید تا صفحه کامل لود شود؛ اتصال اینترنت را چک کنید |
| «Target time already passed» | زودتر شروع کنید یا `--time` دیرتری بدهید |
| «سفارش پس از تمام تلاش‌ها پذیرفته نشد» | بررسی دستی؛ ممکن است بورس به دلیل قیمت/تعداد رد کرده باشد |
| کد `11000` / `8702` در لاگ | بازار باز نیست (یا بسته شده). ربات این‌ها را رایگان دوباره می‌فرستد؛ اگر `API_PREOPEN_MAX_ATTEMPTS` تمام شود یعنی ساعت هدف از ۸:۴۵ دور است یا امروز بازار تعطیل است |
| کد `8006` در لاگ | ارزش سفارش کمتر از حداقل **۵۰۰ هزار تومان** است — `QUANTITY` را بالا ببرید |
| Ctrl+C قبل از ارسال خرید | فوراً متوقف می‌شود: `Stop requested — leaving the clock wait`، بعد `Exiting before buy` و خروج با کد ۰. چون رویداد Ctrl+C پروسه‌ی درایور Playwright را هم می‌کشد، در پایان ممکن است `Browser was already closed` ببینید — این خطا نیست (ADR-007) |
| Ctrl+C وسط/بعد از ارسال خرید | ربات هم متوقف می‌شود، ولی هشدار «سفارش‌ها را دستی چک کنید» را می‌دهد — ممکن است سفارش به کارگزاری رسیده باشد |
| `Browser/Playwright session lost` | مرورگر یا درایور از بین رفته (بسته شدن کروم، کرش). خروج با کد ۱؛ چیز دیگری ارسال نمی‌شود |

## حالت API مستقیم (ADR-004)

از نسخه‌ی شاخه `api-method`، ربات به‌صورت پیش‌فرض (`API_MODE=true`) بعد از
ورود با Playwright، بقیه‌ی کارها را با فراخوانی مستقیم API ایزی‌تریدر انجام
می‌دهد: جستجوی نماد، گرفتن سقف قیمت، ارسال سفارش خرید و بررسی سفارش‌ها —
همه از طریق HTTP. هر گام ناموفق در API، خودکار به مسیر قبلی (کلیک در رابط
کاربری) برمی‌گردد.

- غیرفعال‌سازی برای یک اجرا: `python main.py --no-api`
- همچنین متغیر محیطی `API_MODE=false`
- جزئیات اندپوینت‌های کشف‌شده و دلایل ایمنی: [docs/adr/004](docs/adr/004-hybrid-http-api-mode.md)

⚠️ اندپوینت‌ها رسمی و مستند نیستند؛ ممکن است هر زمان تغییر کنند. ربات در این
صورت به مسیر UI برمی‌گردد ولی نتیجه‌ی سفارش‌ها را حتماً خودتان بررسی کنید.

### فاصله‌ی سفارش‌ها و پنجره‌ی ثبت سفارش

بازار **۸:۴۵:۰۰ تا ۱۲:۳۵:۰۰** است و کارگزاری سفارش‌های جدید را **۸:۴۵ تا
۱۲:۳۰** می‌پذیرد و دو سفارش نزدیک‌تر از **۳۰۰ میلی‌ثانیه** را با خطای
`13021 OrderIntervalError` رد می‌کند — همه اندازه‌گیری زنده،
[ADR-006](docs/adr/006-order-cadence-and-window.md).

دو نوع «نه» وجود دارد و نباید اشتباه گرفته شوند:

| پاسخ کارگزاری | معنی | رفتار ربات |
|---|---|---|
| `13021` | دو ارسال با فاصله‌ی کمتر از ۳۰۰ میلی‌ثانیه؛ سفارش به بازار نرسید | بعد از وقفه دوباره، بدون مصرف سهمیه |
| `8702` / `11000` | بازار هنوز باز نشده (یا تمام شده) | قبل از ۸:۴۵: ادامه‌ی ارسال (رایگان)؛ بعد از ۱۲:۳۰: توقف |
| بقیه (`8006`، دامنه‌ی قیمت، موجودی) | رد واقعی سفارش | توقف — پاسخ عوض نمی‌شود |

به همین دلیل ساعت هدف **۰۸:۴۴:۵۸** است: ارسال‌های اول با
`11000 «وضعیت گروه اجازه فعالیت نمی‌دهد»` رد می‌شوند، هیچ هزینه‌ای ندارند و
ربات همان لحظه‌ی ۰۸:۴۵:۰۰ در حال ارسال است. بعد از باز شدن هم ۲۰ ارسال
تازه با فاصله‌ی ۳۵۰ میلی‌ثانیه (حدود ۷ ثانیه) دارد تا در صف خرید جلو
بیفتد. نسخه‌ی قبلی `11000` را «رد سفارش» حساب می‌کرد و ۳ ثانیه قبل از باز
شدن، با پول واقعی، بی‌خیال خرید می‌شد.

## توکن ذخیره‌شده (ADR-005)

بعد از هر لاگین موفق، توکن (JWT) در فایل `TOKEN_CACHE_PATH` ذخیره می‌شود و
اجرای بعدی به‌جای لاگین دوباره، همان توکن را با چند درخواست فقط-خواندنی
(ساعت سرور، لیست سفارش‌ها، نماد و سقف قیمت) بررسی می‌کند. اگر معتبر بود،
لاگین انجام نمی‌شود و ساعت هم از سرور گرفته می‌شود؛ اگر رد شد (۴۰۱)، فایل
حذف و دقیقاً مثل قبل لاگین انجام می‌شود.

```bash
python main.py --no-token-cache   # نادیده گرفتن و ذخیره نکردن توکن
```

**آیا استفاده مجدد از توکن امن است؟** خودِ اپلیکیشن هم توکن نشست را در
مرورگر نگه می‌دارد و با هر رفرش دوباره می‌فرستد؛ توکن ۱۲ ساعته است و
استفاده مجدد از آن در همین بازه رفتار عادی اپ است. خطر رایج «بن شدن» در
کارگزاری‌ها معمولاً از الگوی غیرانسانی (نرخ درخواست بالا، سفارش در
میلی‌ثانیه‌ی باز شدن بازار) می‌آید، نه از بازاستفاده از توکن: به همین دلیل
پالس ساعت هر ۶۰ ثانیه یک‌بار به سرور می‌خورد (نه ۲۰ بار در ثانیه) و تعداد
POST سفارش پیش‌فرض روی ۵ محدود شده است. با این حال این API رسمی نیست،
قوانین کارگزاری ممکن است ورود سفارش خودکار را محدود کند و هیچ تضمینی
وجود ندارد؛ توکن را مثل رمز عبور بدانید (فایل ۰۶۰۰، در گیت نادیده گرفته
می‌شود، روی ۴۰۱ حذف می‌شود). جزئیات کامل: [docs/adr/005](docs/adr/005-cached-api-token.md)
